# Grafana Integration for Goose Metrics Dashboard

This guide explains how to set up Grafana to visualize metrics from Goose scripts.

## Overview

The Grafana integration provides:
- Advanced visualization options (graphs, heatmaps, stat panels, etc.)
- Real-time dashboards with auto-refresh
- Alerting integration with notification channels
- Dashboard sharing and templating
- Better performance for large datasets
- Integration with Prometheus (if Prometheus exporter is running)

## Prerequisites

- Grafana instance (local or remote)
- Metrics JSON files being generated by Goose scripts (in `/tmp/goose-logs/` by default)
- Optional: Prometheus server and exporter (for better performance)

## Setup Options

### Option 1: Prometheus Datasource (Recommended)

This option provides the best performance and supports advanced PromQL queries.

#### Step 1: Start Prometheus Exporter

The Prometheus exporter converts JSON metrics files to Prometheus format and serves them via HTTP.

```bash
cd goose/scripts
./prometheus-exporter.sh --port 9090 --metrics-dir /tmp/goose-logs
```

The exporter will be available at `http://localhost:9090/metrics`.

#### Step 2: Configure Prometheus (if using Prometheus server)

If you're using a Prometheus server, add this scrape configuration to `prometheus.yml`:

```yaml
scrape_configs:
  - job_name: 'goose-scripts'
    scrape_interval: 30s
    static_configs:
      - targets: ['localhost:9090']
```

#### Step 3: Configure Grafana Data Source

**Method A: Using File-Based Provisioning (Recommended for Production)**

1. Copy the provisioning file to Grafana's provisioning directory:
   ```bash
   sudo cp goose/scripts/grafana-provisioning-datasources.yaml /etc/grafana/provisioning/datasources/goose-prometheus.yaml
   ```

2. Restart Grafana:
   ```bash
   sudo systemctl restart grafana-server
   ```

**Method B: Manual Configuration via UI**

1. Open Grafana UI (usually `http://localhost:3000`)
2. Go to Configuration → Data Sources
3. Click "Add data source"
4. Select "Prometheus"
5. Set URL to `http://localhost:9090` (or your Prometheus server URL)
6. Click "Save & Test"

#### Step 4: Import Dashboard

1. In Grafana, go to Dashboards → Import
2. Click "Upload JSON file"
3. Select `goose/scripts/grafana-dashboard-goose.json`
4. Select the Prometheus data source
5. Click "Import"

### Option 2: JSON Datasource (Alternative)

This option works without Prometheus but has limited query capabilities.

#### Step 1: Install JSON Datasource Plugin

```bash
grafana-cli plugins install marcusolsson-json-datasource
```

Or install via Docker:
```bash
docker exec -it grafana grafana-cli plugins install marcusolsson-json-datasource
```

Restart Grafana after installation.

#### Step 2: Configure JSON Datasource

1. Go to Configuration → Data Sources
2. Click "Add data source"
3. Search for "JSON" and select "JSON API"
4. Configure:
   - **Name**: Goose JSON Metrics
   - **URL**: `http://localhost:8000` (if using `serve-metrics-dashboard.py`)
   - **Path**: `/api/metrics`
5. Click "Save & Test"

#### Step 3: Modify Dashboard for JSON Datasource

The provided dashboard is optimized for Prometheus. For JSON datasource, you'll need to:
- Update panel queries to use JSON API format
- Adjust metric field names to match JSON structure

## Dashboard Features

The dashboard includes the following panels:

1. **Execution Duration Trends** - Time series graph showing script execution duration over time
2. **Success Rate Over Time** - Line chart showing success rate trends
3. **Overall Success Rate** - Stat panel with color-coded thresholds
4. **Total Executions** - Count of total script executions
5. **Average Duration** - Average execution time across all scripts
6. **Errors and Warnings** - Total count of errors and warnings
7. **Errors and Warnings Over Time** - Bar chart showing error/warning trends
8. **Script Performance Comparison** - Bar gauge comparing script execution times
9. **Top Failing Scripts** - Table showing scripts with most failures
10. **Recent Executions** - Table of recent script executions with details

### Dashboard Variables

The dashboard includes a variable for filtering:
- **Script Name**: Filter by specific script(s) or view all scripts

## Alert Rules

Alert rules are defined in `grafana-alert-rules.yaml`. To use them:

1. Copy the alert rules file to Grafana's provisioning directory:
   ```bash
   sudo cp goose/scripts/grafana-alert-rules.yaml /etc/grafana/provisioning/alerting/goose-alerts.yaml
   ```

2. Restart Grafana

Or configure alerts manually in Grafana UI:
- Go to Alerting → Alert Rules
- Create new rules based on the queries in `grafana-alert-rules.yaml`

### Available Alerts

1. **High Error Rate** - Triggers when error rate exceeds 10%
2. **Repeated Failures** - Triggers when more than 5 failures occur in 10 minutes
3. **Performance Degradation** - Triggers when execution time increases by 50%
4. **Low Success Rate** - Triggers when success rate drops below 80%
5. **No Executions** - Triggers when no executions are detected for 1 hour

## File-Based Provisioning (Production Setup)

For production deployments, use file-based provisioning to automatically configure Grafana.

### Directory Structure

```
/etc/grafana/provisioning/
├── datasources/
│   └── goose-prometheus.yaml
├── dashboards/
│   └── goose-dashboards.yaml
└── alerting/
    └── goose-alerts.yaml
```

### Setup Steps

1. **Data Sources**:
   ```bash
   sudo cp goose/scripts/grafana-provisioning-datasources.yaml \
        /etc/grafana/provisioning/datasources/goose-prometheus.yaml
   ```

2. **Dashboards**:
   ```bash
   sudo mkdir -p /etc/grafana/provisioning/dashboards/goose
   sudo cp goose/scripts/grafana-dashboard-goose.json \
        /etc/grafana/provisioning/dashboards/goose/
   sudo cp goose/scripts/grafana-provisioning-dashboards.yaml \
        /etc/grafana/provisioning/dashboards/goose-dashboards.yaml
   ```

3. **Alert Rules**:
   ```bash
   sudo cp goose/scripts/grafana-alert-rules.yaml \
        /etc/grafana/provisioning/alerting/goose-alerts.yaml
   ```

4. **Restart Grafana**:
   ```bash
   sudo systemctl restart grafana-server
   ```

## Testing

### Test with Sample Data

1. Generate some test metrics by running scripts:
   ```bash
   cd goose/scripts
   ./clippy-lint.sh
   ```

2. Verify metrics are being generated:
   ```bash
   ls -la /tmp/goose-logs/*-metrics-*.json
   ```

3. Verify Prometheus exporter (if using):
   ```bash
   curl http://localhost:9090/metrics
   ```

4. Check Grafana dashboard:
   - Open Grafana UI
   - Navigate to the Goose Scripts Metrics Dashboard
   - Verify panels are displaying data

### Troubleshooting

**No data in dashboard:**
- Verify metrics files exist in `/tmp/goose-logs/`
- Check Prometheus exporter is running (if using Prometheus)
- Verify data source connection in Grafana
- Check time range in dashboard (default is last 6 hours)

**Prometheus exporter not working:**
- Check port 9090 is not in use: `lsof -i :9090`
- Verify metrics directory path is correct
- Check exporter logs for errors

**Alert rules not working:**
- Verify alert rules file is in correct location
- Check Grafana logs for provisioning errors
- Ensure data source UID matches in alert rules
